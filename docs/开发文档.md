## 1. 项目概览

**Study-Test（全科题库）** 是一套面向「教师—学员」场景的**多科目在线题库与考试系统**，线上地址 `www.xiaoyue.shop`。

- **核心价值**：题库 + 在线考试 + 错题本闭环；AI 自动出题 + 文档导入（Word/PDF/OCR）降低建库成本；一套代码四端覆盖（Web / Electron / Chrome 扩展 / Android）。
- **规模**（2026-10-11 实测）：前端 `src/` 约 70 个源文件（另有 10 个测试文件），后端 `server/src` 17 个 `.js`（不含生成物），迁移脚本 `server/migrations/001~010`。
- **授权**：MIT。

## 2. 系统架构

### 2.1 前端：SPA + 三视图状态机（另有正式考试独立流程）

练习模式状态流转：`welcome`（科目选择）→ `exam`（答题）→ `result`（结果）。

正式考试为独立流程（2026-07 后新增）：`/formal-exam`（学员：选卷→作答→成绩，由 `useFormalExam` 状态机驱动，服务端权威评分）与 `/exams/manage`（教师/管理员：组卷管理）；`/api/exams` 路由承接。

状态管理由 `src/context/AppContext.tsx` 中的 `AppProvider` 组合 **5 个自定义 Hook**，合并为单一 Context 供所有组件消费（另有 `useFormalExam`、`useBackPrevention` 两个页面级 Hook 不在 Context 内）：

```
AppProvider
├── useAuth()          登录/注册/登出、JWT 生命周期、角色切换、EmailJS 邮箱验证
├── useToast()         轻量通知
├── useUIState()       弹窗可见性、用户管理 UI、搜索/导出状态
├── useQuestionBank()  题目、科目、错题、收藏，挂载时从 API 加载
└── useExam()          考试会话、计时器、作答、评分、错题追踪
```

> **关键约定**：除 JWT Token 存 `localStorage` 外，业务数据**不落地本地**（无 IndexedDB 缓存），所有数据挂载时从 API 拉取——保证多端一致，但强依赖网络（离线不可用）。

### 2.2 后端：Express + MySQL

入口 `server/src/index.js`：加载 `.env` → 配置 CORS 白名单 → 挂载 `/api/*` 路由 → 生产环境托管 `dist/` 静态文件（SPA 回退）→ 代理百度 OCR。

### 2.3 数据流

```
浏览器(React) ──fetch(JWT Bearer)──▶ ApiClient(src/services/api.ts)
        │                                      │
        ▼                                      ▼
   Component/Hook ◀── JSON ── Express 路由 ──▶ mysql2 连接池 ──▶ MySQL
```

## 4. 环境搭建

### 4.1 要求

- Node.js **18+**（推荐 20.x LTS）
- MySQL **5.7+** 或 MariaDB 10.4+
- npm 9+

### 4.2 安装依赖

```bash
npm install --legacy-peer-deps          # 前端（仓库根）
cd server && npm install --legacy-peer-deps && cd ..   # 后端
```

### 4.3 环境变量

复制 `server/.env.example` 为 `server/.env` 并填写：

```env
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_password
DB_NAME=study_test
JWT_SECRET=<用 openssl rand -hex 32 生成，生产环境强制 ≥16 字符、建议 ≥32>
# 可选：JWT 有效期（默认 7d）
# JWT_EXPIRES_IN=7d
# 可选：CORS 白名单（逗号分隔；为空仅同源）
# ALLOWED_ORIGINS=https://www.xiaoyue.shop,http://localhost:3000
# 可选：百度 OCR（扫描件识别）
BAIDU_API_KEY=
BAIDU_SECRET_KEY=
# 可选：服务端 Gemini 代理（仅此一项 Key 走服务器，前端不打包）
GEMINI_API_KEY=
# 可选：信任代理（Nginx 后设为 1）
TRUST_PROXY=1
PORT=3100
NODE_ENV=development
```

> 前端 AI Key 通过 `src/config/apiConfig.ts` 读取 `sessionStorage`（用户在「设置」页填写），**不写入仓库**。生产构建时 `vite.config.ts` 的 `define` 会把这些 Key 剥离为空串，杜绝泄露。

### 4.4 数据库初始化

```bash
cd server
npm run migrate          # 自动按序应用 server/migrations/*.sql，幂等（已应用则跳过）
npm run migrate:status   # 查看已应用 / 待应用
```

> 首次在已初始化数据库上接入，可 `node src/migrate.js --baseline` 仅打基线不重复执行。

## 5. 前端开发

### 5.1 启动

```bash
npm run dev        # Vite 前端，端口 3000（vite.config.ts server.port=3000），/api 代理到 http://127.0.0.1:3100
npm run lint       # tsc --noEmit 类型检查
npm run build      # 生产构建到 dist/（prebuild 自动同步判分模块）
npm test           # vitest 单元测试
```

### 5.2 vite.config.ts 关键约定

- **`@` 别名**解析到**仓库根**（如 `@/src/types`、`@/server/src/db.js`），`vite.config.ts` 与 `tsconfig.json` 同步配置。
- **API 代理**：开发环境 `/api` → `127.0.0.1:3100`。
- **生产安全**：`define` 在生产模式将所有 `process.env.*_API_KEY` 置空，仅保留 `DEFAULT_AI_MODEL` 等开关；Gemini 可走 `/api/ai` 服务端代理。
- **构建产物**：`base: './'`、手动分包（vendor-react/motion/lucide/pdf/ai）、`fix-html-paths` 插件把 `/assets/` 改为 `./assets/` 以兼容 Electron/file 协议。

### 5.3 状态管理（5 Hooks）

| Hook | 职责 | 关键导出 |
|---|---|---|
| `useAuth` | 认证、角色 | `user, login, register, logout, convertRole, bindTeacher` |
| `useToast` | 通知 | `toast(message, type)` |
| `useUIState` | UI 状态 | 各弹窗 `open/close`、搜索/导出态 |
| `useQuestionBank` | 题库 | `subjects, questions, mistakes, favorites, load*` |
| `useExam` | 考试会话 | `startExam, answer, submit, timer, result` |

新增全局状态请归入相应 Hook，再通过 `AppProvider` 合并进 Context，避免散落 props。

### 5.4 关键服务

- `services/api.ts`：`ApiClient` 封装 `fetch`，自动附加 JWT、处理 401（清除 token 并派发 `auth:expired`）。导出命名 API 对象（含 inviteCodeApi/studentApi/healthApi），组件/ Hook 直接调用；正式考试走 `services/examApi.ts`。
- `services/api.mappers.ts`：双轨类型映射层（R6），网络 DTO 仅在 api 边界出现，消费方只见领域类型；新字段接入时在此补映射并同步单测。
- `services/geminiService.ts`：AI 出题核心（见 §9）。
- `services/extract/`：导入解析器族（CSV/Excel/Word/PDF/MD/OCR/Gemini 视觉，懒加载重型依赖）。
- `shared/scoring/index.ts`：判分**单一事实源**（`isAnswerCorrect`/`gradeQuestion`/`scoreByIndices` 等），框架无关，附 28 个 vitest 用例；`utils/examScoring.ts` 仅为兼容壳。**改判分只改此文件，然后跑 `npm run sync:scoring`（已挂 prebuild）**同步生成后端 `examScoring.generated.js` 与扩展 `scoring.js`。

### 6.3 服务端 AI 代理（routes/ai.js）

- 仅代理 **Gemini**，Key 来自环境变量 `GEMINI_API_KEY`（前端不持有）。
- 内存限流：每用户 10 次/分（用 `Map`，多实例部署会失效，见 §12 P1）。
- 请求体限制 100KB，防滥用。

## 7. 数据库设计

### 7.1 核心表（12 张，由迁移 001~010 演进）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `users` | role(admin/teacher/student/independent)、status(active/pending)、teacher_id | 用户与师生关系 |

| `mistake_records` | user_id+question_id 唯一、consecutive_correct(连对 3 自动移除) | 错题本 |
| `favorites` | user_id+question_id 唯一 | 收藏 |
| `study_stats` | subject、study_time、correct_count… | 学习统计 |
| `invite_codes` | type(registration/subject)、scope、max_uses | 邀请码 |
| `subject_subscriptions` | user_id+subject_id 唯一、status(pending/approved/rejected) | 订阅 |
| `subject_student_access` | 白名单 | 仅学员可见科目的授权 |
| `visit_counter` | 单行 | 访问计数 |
| `exams`（010） | subject_id、question_set(JSON: [{question_id,points}])、total_points、duration_minutes、start/end_time、pass_score、status(draft/published/closed) | 正式考试试卷定义 |
| `exam_attempts`（010） | exam_id+user_id（**非唯一**，支持多次参考取最高分）、status(in_progress/submitted/auto_submitted)、answers(JSON)、details(JSON)、score、deadline(服务端计时基准) | 学员答卷 |

### 7.2 迁移机制

- 编号文件 `server/migrations/NNN_*.sql`，由 `server/src/migrate.js` **按序自动应用**，状态记入 `schema_migrations` 表（幂等）。
- 新增迁移：放一个 `NNN_name.sql` 到 `server/migrations/`，下次部署自动执行。
- ⚠️ 建表必须**显式指定 `COLLATE=utf8mb4_unicode_ci`**：连接层排序规则可能为 gbk / utf8mb4_0900_ai_ci，仅写 `DEFAULT CHARSET=utf8mb4` 会导致外键报 "are incompatible"（010 已如此处理）。
- 历史临时脚本（`run-00X.js`）已归档在 `server/migrations/archive/`。
- ⚠️ **无统一迁移框架**（Knex/Flyway）。`008_fix_schema_mismatch.sql` 的存在表明历史上出现过 schema 漂移。建议后续引入框架并纳入 CI（见 §12）。

## 8. API 参考（端点清单）

> 通用：除 `/api/health`、登录/注册外，均需在 Header 携带 `Authorization: Bearer <token>`。错误体形如 `{ "error": "..." }` 或 `{ "message": "..." }`。

### 8.1 认证 `/api/auth`
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/auth/register` | 注册（role/inviteCode/teacherPhone 可选） |

- 数据：`questions.audio_url`（迁移 026，可空 VARCHAR(300)，存 `/api/uploads/...` 相对路径，软引用上传文件、**无外键**）。听力不是新题型——仍是普通题（single/fill_in/…），判分/题型枚举零改动。

### 8.3d 编程题在线判题（FR-106）

- 数据：`question_judge_configs`（迁移 027，question_id 主键，软引用 questions **无外键**）存 language/time_limit_ms/memory_limit_mb/starter_code/test_cases(JSON)/created_by/org_id；`judge_runs`（迁移 028）为异步判题状态机（queued/running/done/failed/skipped + verdict AC/WA/TLE/MLE/RE/CE + passed/total/time_ms/mem_kb/log）。**`questions` 表与 SSOT 判分主流程（src/shared/scoring）零改动**，分数真相仍在 `exam_attempts.details`。
- Runner 接口化：`judgeService.getRunner()` 由环境变量 `JUDGE_RUNNER` 切换——生产 `docker`（每提交起一次性容器、禁网/只读/非root/超时内存限额），测试 `stub`（用例通过当且仅当提交代码包含归一化期望输出首行子串）；并发闸 `acquireSlot/releaseSlot`。fail-closed：docker 不可用/超时/异常回落 `needs_manual`。
- 建题写入：`POST /questions`、`POST /questions/batch`、`PUT /questions/:id` 接受 `judge_config`（含 test_cases 数组）写 `question_judge_configs`（update 用 ON DUPLICATE KEY UPDATE，`judge_config===null` 则删除）；`GET /questions/:id` 详情带出 `judge_config`。**注意 mysql2 已自动解析 JSON 列**，读取须 `typeof==='string'?JSON.parse:值本身`（或 `parseJsonSafe`），不可直接 `JSON.parse(array)`。
- 练习同步：`POST /api/judge/practice { question_id, code }`——带**属主/共享可见性校验**（与题目详情同一谓词，不可见 404，防跨租户越权触发判题/隔空探测期望输出），跑 `is_sample` 用例（无则全部），返回 `{verdict, passed, total, perCase, time_ms}`，不计分不入库。
- 考试交卷异步：submit commit 后 `enqueueProgrammingJudges`→`runJudge`（Docker/Stub）→`writeJudgeScoreToAttempt`：`SELECT ... FOR UPDATE` 事务内 `applyJudgeScore` 回写 details/score/correct_count，`earned=round(points*passed/total)`；判完（无 needs_manual）发 `score_ready` 通知，复用 FR-103 链路，前端无需轮询。
- 隔离进门禁：`isolation.integration.mjs` FR-106 段断言 B 读 A 编程题 config / 借 practice 触发均 403/404。
- 前端：`QuestionForm` 编程题配置区（初始代码 + 样例用例增删，透传 `judge_config`）；练习页「运行样例」按钮 + 逐用例结果面板（`judgeApi.practice`）；考试页编程题「判题中，成绩稍后更新」提示。契约 `src/types.ts`（JudgeConfig/JudgeRunResult）+ `judgeApi`。

### 9.2 三级 Key 降级策略（geminiService.ts）

1. **用户 Key**：`sessionStorage` → `localStorage` 中的 AI 设置（用户自有，最优先）。
2. **开发构建注入**：`vite.config.ts` 的 `define`（仅 `import.meta.env.DEV` 生效，生产为空）。
3. **服务端代理**：`/api/ai/gemini/generate`（Key 仅存服务器环境变量，带限流与体积限制）。

> 这是合理的密钥隔离设计：生产构建不把任何 Key 打进前端包。

### 9.3 题型与评分（shared/scoring 单一事实源）

- `single`：选项字母或文本双向匹配（A ↔ options[0]）。
- `multiple`：排序后比较数组；支持字母标签到文本映射。
- `programming`：练习模式字符串归一化（去空白、引号统一、转小写）后判等；**正式考试中不自动判分**（`gradeQuestion` 返回 `is_correct=null、needs_manual=true`，留待人工评阅）。**不做代码执行**，对格式敏感。
- 跨端同步：`npm run sync:scoring`（已挂 `prebuild`）由 `scripts/build-scoring.mjs` 从 `src/shared/scoring/index.ts` 生成后端 `server/src/utils/examScoring.generated.js`（ESM）与扩展 `chrome-extension/scoring.js`（IIFE，全局 `StudyScoring`）。⚠️ 现状：`exams.js` 仍引用手写副本 `server/src/utils/examScoring.js`（与生成版逻辑一致但双轨并存，属待收敛技术债，见 §12）。

### 9.4 文档导入与公式识别

- 支持格式（导入面板文件选择框）：`.pdf / .docx / .doc / .txt / .md / .csv / .xlsx / .xls / .json`；Excel/CSV/JSON 直接结构化解析，其余走文本抽取 + AI/规则解析。
- Excel/CSV 解析（`extract/xlsxExtract.ts`、`csvExtract.ts`）：只读第一个 sheet；列名中英别名（题型/题目/选项/答案/解析/分值/代码/输入）；必选三列 type+title+answer；Excel 专有增强：单元格内换行（Alt+Enter）可作选项分隔；缺省分值 5。SheetJS 属重型依赖，**必须函数内 `await import('xlsx')` 动态加载，严禁顶层静态引入**。
- OCR 四条链路：离线 tesseract.js（本地资产 `npm run setup:tesseract`，初始化 45s 超时防 CDN 卡死）、在线百度高精度（经服务端 `/api/ocr/baidu` 代理）、Gemini 视觉（`extract/aiVision.ts`）、PaddleOCR AI Studio（需 Token，localStorage 配置，环境变量 `VITE_PADDLEOCR_API_KEY` 可选）。
- 公式支持**已上线**（原 `PLAN-formula-support.md` 计划完成并归档）：`MarkdownRenderer` 挂载 remark-math + rehype-katex 渲染 LaTeX 公式；导入时公式识别开关默认开启（图片公式 → LaTeX，失败保留原图）；KaTeX 中文控制字符告警已抑制。
- `fileService.ts`：mammoth 抽 Word 文本/图片；pdfjs-dist 抽 PDF，无文本层降级 OCR。
- `mdParserService.ts`：标准化 MD（`### 题型 | 分值:5 | 难度:基础`）与宽松纯文本双解析器。
- 大列表性能：导入预览 `PreviewList` 基于 `ui/VirtualList`（react-window 虚拟滚动）。

### 9.5 已知限制

- `hunyuan`/`ernie` 仅有路由分支但未实现（抛错引导走 OpenRouter）。
- Gemini 文件直传 `parseQuestionsWithFile` 仅 Gemini 支持。

### 10.7 跨租户隔离集成测试（Phase 2 / M1 安全网）

面向真实 HTTP + 真实 MySQL 的集成测试（区别于 `tests/unit` 的 vitest 单测），需后端已启动（CI 由 `isolation-test` job 自动 boot）。

| 文件 | 职责 |
|---|---|
| `server/tests/helpers/integrationHarness.mjs` | 公共桁架：`resolveDbConfig`（env 三级回退 `EXAM_IT_DB_* → DB_* → 默认`）、`api`、`check`、`reportExit`、`registerWithCode`（兼容生产邮箱验证码强校验）、`checkBlocked`（403/404 越权口径）。凭据全走 env，无硬编码口令；自动加载 `server/.env`（dotenv 不覆盖已存在 env，故 CI 显式优先）。 |
| `server/tests/integration_exam.mjs` | 考试全链路 E2E（141 断言），已重构为复用桁架。 |
| `server/tests/isolation.integration.mjs` | **M1 核心**：两个 PERSONAL 租户（teacherA/B 各带学员 sA/sB），断言 B 读不到 A 的 questions/subjects/exams/exam_attempts/mistake_records/favorites/study_stats/question_tags（现 33 断言：32 条硬门禁 + 1 条 KNOWN-GAP 软告警）。 |

**关键设计**：
- **零生产行为变更**：冻结“现有属主隔离”作回归基线，不改 `server/src`。
- **防假绿**：所有“B 列表/树不含 A 记录”的负向断言均配同端点/同键的“**A 确有**”正向对照，并将夹具 id 真值守卫内嵌（缺失即显式判红）。
- **数据安全**：cleanup 的 `LIKE` 模式均转义下划线（`\_`）防误删真实数据；`resolveDbConfig` 带非测试库护栏（库名不含 `test`/`ci` 则拒运行，除非 `EXAM_IT_ALLOW_UNSAFE_DB=1`）。
- **KNOWN-GAP**：`GET /tags/question/:id` 存在真实读侧越权缺口（不校验题目归属），M1 记为一条恒定 `ok:true` 的软告警断言（不进硬门禁、名称可 grep），待 **WS-2** 修复；修复后名称会提示下线软告警。

**本地运行**（需先启动后端；Windows 下用 `127.0.0.1` 规避 `localhost→::1`）：
```powershell
$env:EXAM_IT_BASE='http://127.0.0.1:3100/api'; node server/tests/isolation.integration.mjs
```

## 13. 快速排错

| 现象 | 排查 |
|---|---|
| 前端 401 反复登出 | 检查 JWT_SECRET 是否变更；token 过期会清除并派发 `auth:expired` |
| 迁移失败 | 确认 `server/.env` 正确；`npm run migrate:status` 看基线 |
| AI 出题 503 | 服务端未配 `GEMINI_API_KEY` 且用户未填 Key；或走代理被限流 |
| PDF 无文本 | 扫描件需 OCR（百度 AK/SK 或前端 tesseract），否则解析为空 |
| 端口占用 | `fuser -k 3000/tcp` / `fuser -k 3100/tcp` |
| CORS 报错 | 在 `server/.env` 的 `ALLOWED_ORIGINS`（逗号分隔）加入当前 origin 并重启后端 |
